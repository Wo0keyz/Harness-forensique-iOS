CodeHarness-forensique-iOS, iLEAPP-MCP

Le harness fait lire à un modèle de langage local tout le contenu d'un iPhone extrait avec iLEAPP. Il en tire des scénarios d'enquête, instruits à charge et à décharge, et rédige un rapport dont chaque phrase renvoie à une preuve numérotée qu'on peut relire.

Un téléphone saisi, c'est des centaines de milliers de lignes : messages, applications, réseaux, fichiers, lieux. Un enquêteur ne peut pas tout lire. Un modèle de langage le peut, mais il peut aussi inventer. Le harness encadre donc le modèle : le code extrait les preuves, vérifie chaque affirmation et assemble le rapport. Ce qui n'est pas vérifié n'est pas imprimé.

Un outil d'aide, pas un expert Le rapport est un brouillon de travail pour l'analyste. Il ne conclut jamais à la culpabilité de quelqu'un, il s'arrête avant publication pour être relu et validé nominativement, et la qualification juridique revient au magistrat. Le catalogue d'infractions est un projet à faire valider par un juriste.

Le principe

Le code extrait et vérifie, le modèle raisonne. Tout ce qui peut être fait de façon déterministe est fait par du code. Le modèle de langage n'intervient que là où il faut lire et relier, et il est contrôlé à chaque sortie.

Code déterministe

Lit les exports par nom exact, numérote chaque ligne de preuve, relève la fiche du terminal, contrôle chaque constat du modèle, plafonne les verdicts, assemble le rapport, scelle le dossier d'exécution.

Modèle raisonne

Lit les communications et l'activité, note des signaux neutres, formule des scénarios, instruit chacun avec des outils en lecture seule, joue la défense, rapproche d'un catalogue d'infractions, rédige.

Analyste décide

Relit le brouillon, preuves en main, puis le valide (nominativement) ou le rejette (avec un motif). Le rapport final porte cette décision en tête.

Ce qui est garanti, ce qui ne l'est pas

Garanti par le code

  • Chaque phrase du rapport cite au moins une preuve qui existe et qui a été montrée au modèle.
  • Chaque citation recopiée se retrouve dans la ligne de preuve citée.
  • Chaque date et chaque heure écrites figurent dans les preuves citées.
  • L'auteur d'un message n'est pas contredit par l'expéditeur ou le sens du message cité.
  • Aucun scénario « étayé » sans deux éléments à charge vérifiés, appuyés sur deux preuves distinctes.
  • Les preuves ne sont jamais modifiées, et toute modification pendant l'analyse est signalée.
  • Aucune donnée de dossier n'est envoyée à un service en ligne : le traçage cloud est coupé dans le code, les traces restent dans un Langfuse local.

Pas garanti

  • Le sens d'une phrase : citer la bonne ligne en l'interprétant mal passe le contrôle.
  • L'exhaustivité : des faits présents dans le téléphone peuvent manquer au rapport.
  • La reproductibilité au mot près : deux exécutions peuvent différer, c'est mesuré.
  • L'identité de l'analyste qui valide : son nom est déclaratif.
  • La qualification juridique : le catalogue est un projet, et la décision revient au magistrat.

Résultats actuels

Campagne terminée le 13 octobre 2026 : 35 exécutions de bout en bout, sur une copie figée du code, sans cache. Magnet est une image iOS publique (CTF) avec 18 faits et 3 scénarios connus ; Hickman, une image iOS 17 publique sans infraction, jamais utilisée pour régler le harness ; les deux témoins sont synthétiques, et le bon résultat y est de ne retenir aucun scénario.

Démarrage rapide

Prérequis : une sortie iLEAPP, le serveur d'inférence llama.cpp démarré, et les deux dépôts clonés côte à côte. L'installation complète, depuis une machine vierge, est dans la documentation technique.

git clone -b feat/harness-provenance https://github.com/Wo0keyz/iLEAPP-MCP.git
git clone https://github.com/Wo0keyz/Harness-forensique-iOS.git forensic-langgraph

cd forensic-langgraph
uv sync                                   # environnement à partir de uv.lock
cp .env.example .env && chmod 600 .env    # puis renseigner les clés Langfuse
uv run pytest                             # 112 tests, sans modèle

# coût prévu (lots, tokens), sans appeler le modèle
uv run python -m forensic_harness /chemin/vers/sortie_iLEAPP --plan

# analyse ; s'arrête sur un brouillon à valider (code de sortie 3)
uv run python -m forensic_harness /chemin/vers/sortie_iLEAPP

# décision de l'analyste sur ce brouillon-là
uv run python -m forensic_harness --resume runs/<cas>/<exécution> \
    --draft-sha256 <empreinte> --approve --analyst "Nom"

# contrôle a posteriori d'une exécution scellée
uv run python -m forensic_harness --verify runs/<cas>/<exécution> --manifest-sha256 <empreinte notée>
